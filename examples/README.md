# Examples

Small, synthetic, publication-safe inputs used by the documentation, the
tests and the extension's contract tests. None of them is a real trace.

| File | Format | Use |
|---|---|---|
| `traces/minimal-session.json` | `cui-trace-v1` browser export | Legacy-format example (read-only) |
| `traces/minimal-session-v2.json` | `cui-trace-v2` browser export | Current-format example |
| `detector/synthetic-dataset.json` | `cui-detector-dataset-v2` | 18 synthetic records (3 tasks x 2 classes x 3 repetitions) for the detector pipeline |

```sh
computer-use-agent validate --schema cui-trace-v2 --input examples/traces/minimal-session-v2.json
computer-use-agent validate --schema cui-detector-dataset-v2 --input examples/detector/synthetic-dataset.json
computer-use-agent analyze --dataset examples/detector/synthetic-dataset.json --output-dir out/run1 --profile smoke
computer-use-agent view --trace demo=examples/traces/minimal-session-v2.json --port 0
```

`detector/synthetic-dataset.json` is generated by `tests/fixtures/synthetic.py`
(`python -m tests.fixtures.synthetic examples/detector/synthetic-dataset.json`)
and a test keeps the two byte-identical. Any analysis of it is labelled a
synthetic pipeline check, never a detector result.
